# File Explorer

File Explorer is a native userspace `.wiz` app, available from Start or with:

```text
run /bin/explorer.wiz
```

It ships in the normal initrd and ext4 system image. Updating an existing image
adds it without requiring `FRESH=1`. Its build output is
`build/packages/explorer.wiz`; source is `user/explorer.cpp`.

## Browsing

- Home, Applications, App samples, Installed apps, System and Devices are in the sidebar.
- Double-click a folder or select it and press Enter to open it.
- Use Back, Forward, Up and Refresh; Backspace goes to the parent folder.
- Click the address bar, or press Ctrl+L, then enter an absolute or relative path.
- Up/Down selects rows; the mouse wheel scrolls. Hidden toggles dotfiles.
- Folders sort before files, with names sorted without regard to ASCII case.

## Files and apps

- Double-click `.wiz` and `.elf` programs to launch them. Explorer remains usable
  while they run. GUI apps are independent; console apps get a private terminal
  window. Closing Explorer leaves launched programs running. Double-click runs
  a package; select it and use Install to install it.
- Select a `.wiz` and choose Install or Pin to use the same verified package
  manager as the shell. Downgrades remain refused. Reopen Start to refresh it.
- Other files open a read-only text preview of up to 4 KiB. Binary files show a
  message that no viewer is installed; image preview and editing are future work.
- New folder, New file and Rename use a name dialog. Enter confirms; Escape cancels.
- Copy/Cut and Paste work across folders. File copies are staged under an
  exclusive hidden temporary name, synchronized, then renamed without overwrite.
  A failed copy keeps the original. Existing destination names are never overwritten.
- Cut/Paste can move files and directories within the same filesystem. Recursive
  folder copying and cross-filesystem moves are not implemented yet.
- Delete asks for confirmation. It removes files and empty folders only; it
  refuses nonempty directories. There is no trash or undo.

Ctrl+C/Ctrl+X/Ctrl+V copy, cut and paste in Explorer. Ctrl+C in a private console
interrupts that console's program, and Ctrl+C in the main Terminal affects only
its foreground console program. Neither cancels an unrelated Explorer window.

The first version uses the built-in Selawik atlas and printable ASCII. Names
are stored intact, but unsupported glyphs render as `?`. Listings are bounded
to 512 visible items and report when truncated. The window has a fixed client
size of 860 by 560 pixels, matching the current non-resizable window API.

## Implementation and verification

`user/native_ui.h` provides the small userspace syscall and surface drawing
helpers. Filesystem calls use the existing VFS ABI. Syscall 212 (`TRYWAIT`)
adds a nonblocking exact-child wait without changing the existing two-argument
`WAITPID` ABI. Package ABI 3 adds `LAUNCH` (213) and private console channels
(214); Explorer requires ABI 3. Existing ABI 1/2 apps remain supported. Icons are geometric PNGs generated by
`python3 tools/create_default_icons.py --only explorer`.

Explorer's file rows use small antialiased vector drawings: connected gold
folders, paper documents and purple wizard hats for `.wiz` packages. Rounded
toolbar buttons share the violet/gold palette, include action glyphs where they
fit, highlight on hover and dim actions that do not apply to the selection.

```sh
make test-explorer
make iso PERSIST_DISK=.storage-test/explorer-seed.img ROOT_MIB=64
python3 tests/qemu_explorer_test.py
```

Host tests run the real Explorer operations and input handling against a sandbox
with ASan/UBSan, including failed-copy cleanup, existing-name protection, sorting,
navigation, previews and launch bookkeeping. They also render
`.storage-test/explorer-host.png`. The QEMU test boots a disposable seed copy,
checks the actual nonblocking wait syscall, launches Explorer from Start, uses
real mouse/keyboard input, launches console and GUI apps, and validates saved
files with the Linux ext4 checker. Screenshots are in `.storage-test/`.
