WyzarOS build configurations (WSL)
================================

Close QEMU before rebuilding its image. From WSL:

cd /mnt/c/Users/kaihe/Downloads/MyOS

Run normally, preserving saved files:
make clean && make run

Run fresh, RESETTING saved files/settings:
make clean && make run FRESH=1

Run a fixed 256 MiB debug root, preserving an existing debug image:
make clean && make run DEBUG=1

Reset to a fresh fixed-size debug image:
make clean && make run FRESH=1 DEBUG=1

Build ISO/USB images without launching QEMU, preserving saved files:
make clean && make iso
Supported Intel GPUs now automatically attempt composition and page flips.
Unsupported hardware or failed checks retain CPU rendering/presentation.

Experimental Intel Gen9 opaque compositor and GPU rainbow (hardware testing):
make clean && make iso GPU_COMPOSE=1 GPU_PRESENT=0
This implies GPU=1. Boot must report offscreen composition readback PASSED and
dirty CPU/GPU cache coherence PASSED before enabling it. The HUD then shows
GPU:opaque+rainbow LLC. Failure retains/rebuilds the CPU path. Composition-mode
boot tests stay offscreen; GPU=1 alone retains visible developer diagnostics.
Chrome, alpha blending, scaled surfaces and screen presentation remain on the
CPU in this mode. The owner reported 24% CPU fullscreen versus 60% in CPU mode.

GPU presentation (same-mode double buffering, now enabled by default):
make clean && make iso
GPU, GPU_COMPOSE and GPU_PRESENT default to enabled, with runtime checks.
Kernel objects now
rebuild automatically when compiler/GPU flags change. Boot Log explicitly
reports whether page flipping was requested or disabled by the build.
Supported linear firmware planes use two hidden scanout buffers and
vblank-latched flips instead of CPU live-screen
copies. The HUD must show GPU:opaque+rainbow flip UC and Boot Log must report
GPU: first vblank page flip latched. Unsupported layouts retain CPU presentation.
The rest of GUI rasterization (fonts, icons, alpha, general scaling) is still CPU.
For the previously tested presenter, rebuild with GPU_COMPOSE=1 GPU_PRESENT=0.

Gen9 render-engine scaling (enabled by default on validated hardware):
make iso
RCS follows GPU_COMPOSE. Runtime discovery and short offscreen readback checks
select acceleration or CPU fallback. GPU_RENDER=0 keeps blitter composition.
GPU=0 disables GPU paths, including RCS, without requiring additional flags.
GPU_TRACE=1 enables stage tracing and lengthy ring/resize startup stress sweeps.
Normal builds use GPU_TRACE=0. Fonts, icons and general alpha layers use CPU.
The owner reported a 900-second stable v10 run on the ThinkPad at 256 MiB,
with resizing, overlapping and restarts, and smooth direct rendering on v11.
QEMU fallback tests exercise CPU recovery; Intel execution needs hardware.

Force the CPU renderer, preserving saved files:
make iso GPU=0

Reproduce the measured Kaby Lake retained Rainbow build in wyzar-usb.img:
make iso GPU_RCS_ALPHA=1 GPU_WORKLOAD=1 GPU_OPAQUE_RETAIN=1 GPU_ALPHA_MERGE=1 \
  GPU_ALPHA_REPAIR_BATCH=1 GPU_RETAINED_MENU=1 GPU_CURSOR_SAVE=1 \
  GPU_WIDE_BLITS=1 GPU_EXACT_REPAIRS=1 GPU_FRAME_DIAGNOSTICS=1

Run make iso again to return wyzar-usb.img to the default GPU policy, which
uses CPU SIMD for translucency and enables supported Intel scaling and flips
after runtime checks.

Build fresh images without launching QEMU:
make clean && make iso FRESH=1

For a fresh fixed-size build without QEMU, add DEBUG=1 to that last command.
make run already builds the ISO and refreshes USB files; a preceding make iso
is unnecessary. Source/header edits usually need only make run, not make clean.
Kernel compiler/GPU option changes now trigger automatic object rebuilding.

Flags and outputs
-----------------
- FRESH=1 resets the selected host image; make clean leaves saved images alone.
- Normal fresh images contain a 256 MiB seed and occupy 385 MiB. First boot on
  larger media can prepare a larger root while keeping the original seed.
- DEBUG=1 fixes root at 256 MiB. It controls storage policy, not optimization
  or logging. Switching an enlarged image to debug size requires FRESH=1.
- Flags do not persist between make commands. Repeat DEBUG=1/PERSIST_DISK when
  using separate invocations.
- wyzar-usb.img is the whole USB disk image to flash; wyzar.iso is the ISO.
  Flashing a physical stick replaces its saved data. Host builds do not update
  an already-flashed stick in place.
- PERSIST_DISK=another.img selects another host system image.
- QEMU uses local OVMF.fd or /usr/share/OVMF/OVMF_CODE.fd; override with
  OVMF=/path/to/firmware.fd.
