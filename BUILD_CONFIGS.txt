WyzarOS build configurations (WSL)
================================

Close QEMU before rebuilding its image. From WSL:

cd /mnt/c/Users/kaihe/Downloads/MyOS

Run normally, preserving saved files:
make clean && make run

Run fresh, RESETTING saved files/settings:
make clean && make run FRESH=1

Run a fixed 256 MiB debug root, preserving an existing debug image:
make clean && make run DEBUG=1

Reset to a fresh fixed-size debug image:
make clean && make run FRESH=1 DEBUG=1

Build ISO/USB images without launching QEMU, preserving saved files:
make clean && make iso

Build fresh images without launching QEMU:
make clean && make iso FRESH=1

For a fresh fixed-size build without QEMU, add DEBUG=1 to that last command.
make run already builds the ISO and refreshes USB files; a preceding make iso
is unnecessary. Source/header edits usually need only make run, not make clean.
Clean when changing compiler options such as OPT/GPU.

Flags and outputs
-----------------
- FRESH=1 resets the selected host image; make clean leaves saved images alone.
- Normal fresh images contain a 256 MiB seed and occupy 385 MiB. First boot on
  larger media can prepare a larger root while keeping the original seed.
- DEBUG=1 fixes root at 256 MiB. It controls storage policy, not optimization
  or logging. Switching an enlarged image to debug size requires FRESH=1.
- Flags do not persist between make commands. Repeat DEBUG=1/PERSIST_DISK when
  using separate invocations.
- wyzar-usb.img is the whole USB disk image to flash; wyzar.iso is the ISO.
  Flashing a physical stick replaces its saved data. Host builds do not update
  an already-flashed stick in place.
- PERSIST_DISK=another.img selects another host system image.
- QEMU uses local OVMF.fd or /usr/share/OVMF/OVMF_CODE.fd; override with
  OVMF=/path/to/firmware.fd.
